# GitHub Manager SOP

## Trigger
The execution trigger phrase is `run your sop`.

Interpretation rules:
- execute only when the phrase is used as a direct command
- do not execute when the phrase is quoted, discussed, or used hypothetically

## Steps
1. Freeze the baseline with `git status`, branch, upstream, remotes, and changed files.
2. Classify the worktree into logical change groups.
3. Read diffs and identify correct commit boundaries.
4. Stop if unrelated work cannot be split safely without misrepresenting history or touching user work.
5. Form logical commit batches with expected verification.
6. Run relevant tests for each batch.
7. Stage selectively.
8. Commit in dependency order.
9. Audit each commit.
10. Verify push safety:
    - current branch
    - upstream branch
    - `origin` URL
    - whether the target is a default or protected branch
11. Push the intended branch to GitHub.
12. Verify post-push state:
    - local `HEAD` matches pushed `HEAD`
    - upstream tracking is correct
    - remaining worktree state is reported
13. Report commit list, tests run, branch pushed, and residual risks.

## Push Policy
- Pushing is part of the SOP.
- Do not push directly to a default or protected branch unless the user explicitly asked for that.
- If branch targeting is ambiguous, stop and resolve that before pushing.
